# AGENTS.md

One-file PyTorch library: a forward hook that caps extreme amplitude outliers at
`q_proj` / `o_proj` outputs. No training, no weights, no calibration data. The
operator is ~80 lines; everything else is the measurement harness that produced
the README tables. No CI, no unit-test suite.

## Layout

| path | role |
| :--- | :--- |
| `harmonic_llm/core.py` | operator + `suppression_profile`; all math in `_components` |
| `harmonic_llm/patch.py` | hook attach/detach, global `_ACTIVE_HOOK_HANDLES` registry |
| `harmonic_llm/__init__.py` | 5 public names and `__version__` |
| `test_package_spectrum.py` | the only harness: writes both `doc/*.png` + the JSON behind every README number |
| `doc/*.png` | checked-in figures, regenerated by the harness |
| `dist/`, `harmonic_llm.egg-info/` | build artifacts — never edit |

`get_dct_basis()` in `core.py` is dead code kept for backward compatibility.
The v4 operator is pointwise; it uses no transform and no quantization.

## Environment

The system `python3` has no numpy/torch. Use:

```bash
PY=/home/feifei/develop/unsloth/.venv/bin/python3   # torch 2.x + transformers + matplotlib
```

**Run the harness from the repo root**, with the model path passed explicitly:

```bash
$PY test_package_spectrum.py --model ../gemma-4-12B-it-qat-q4_0-unquantized \
    --max-new-tokens 64 --reps 4 --outdir /tmp/opencode/run1
```

`DEFAULT_MODEL` is `./gemma-...`, which does **not** resolve from the repo root.
Running from the parent directory is worse than it looks: `harmonic_llm` then
resolves to the installed wheel in site-packages, so you silently measure stale
code instead of your edits. From the repo root the local package wins. Set
`HARMONIC_MODEL_ID` instead of `--model` if you prefer an env var.

Fast smoke test before any 12B run (~1 min, no GPU model needed):

```bash
$PY test_package_spectrum.py --model hf-internal-testing/tiny-random-LlamaForCausalLM \
    --prompt "Say hi" --max-new-tokens 8 --outdir /tmp/opencode/smoke --reps 1 --quick
```

`--quick` skips the sham controls and timing. Every run starts with
`bypass_audit()`, which is the closest thing to a test: closed gate must be
bit-identical, open gate must land on `threshold * ref`.

There is no `pip` in that venv. Install with
`uv pip install --python $PY --no-deps --reinstall <wheel>`.

## Operator invariants

These are load-bearing. If an edit breaks one, the package's claims become false.

- **Bit-exact at rest.** A block under the knee gets `gain == 1` exactly; only
  then are untouched activations returned bit-for-bit. Never introduce a path
  that perturbs every element (an earlier int8/DCT round-trip did exactly that
  and suppressed nothing).
- **Elementwise math stays in the input dtype.** No upcast to fp32 — it halves
  throughput and buys nothing here. Only the `ref` reduction is a constant-size
  statistic.
- **Amplitude, not shape.** `ratio = block_peak / median(block RMS)`. Crest
  factor (`peak/rms`) is scale-invariant, so `Δcrest ≈ 0` is by construction and
  is *not* evidence of failure. Do not "fix" it.
- **Scale-equivariant.** Multiplying the tensor by a constant leaves `ratio`
  unchanged; that is why one threshold works across layers.
- **Threshold units are `block peak / median block RMS`**, default `64.0`.
  Healthy bulk sits at 2–4, so the old default of `2.2` gated ~39% of blocks
  (measured on the 12B model); `6.0` still hits ~6% (Q) / ~9% (O) and drove NLL
  from 0.17 to 23. Lower it only after measuring with `suppression_profile`.
- Hooks are global: `apply_harmonic_eq` first removes any existing hooks, and
  `remove_harmonic_eq()` restores the stock model. Keep that contract.

## Measurement pitfalls (all of these produced wrong numbers once)

- **Instantaneous stats must cover the whole sequence, prompt included.** The
  95× Q spike lives in the prompt; restricting the probe to generated positions
  made Q look completely untouched.
- **Cross-condition bf16 comparison needs a tolerance.** bf16 rounding moves
  values by ~0.4%, so a signed median reads 0 while 75% of blocks look
  "changed". Use `|Δ|` and a ~1% threshold.
- **Pair per layer, never `torch.cat` across layers.** In the 12B model, 8 of 48
  layers have 8192-dim Q/O outputs; the rest are 4096. Shapes differ.
- **Teacher-force every condition on the same tokens.** Comparing two independent
  greedy generations attributes text differences to the operator — that is where
  the old "0.06–0.10 dB" figure came from.
- **Cost is real**: ~0.71× tokens/s at batch 1 (pointwise traversal of every Q/O
  output). Don't claim zero overhead.

Reported reference points on `gemma-4-12B-it-qat-q4_0-unquantized` at defaults:
0.001% of Q blocks and 0.07% of O blocks touched, median peak reduction
−21% / −16%, KL 0.092 nats/token, NLL 0.173 → 0.293.

## README numbers

Every table and figure caption in `README.md` is copied from
`harmonic_diagnostics.json` emitted by the harness. If you change the operator,
thresholds, or the harness, rerun it and update the README in the same change —
do not hand-edit the numbers.

## Releasing

This directory is **not** a git checkout. The GitHub repo is a separate clone
(most recently `/tmp/opencode/Harmonic-LLM`); publishing means syncing
`README.md`, `pyproject.toml`, `test_package_spectrum.py`, `harmonic_llm/*.py`
and `doc/*.png` there, then committing and pushing. Check the clone still exists
before relying on it; `/tmp` is not durable.

Version lives in exactly two places and must match:
`pyproject.toml` and `harmonic_llm/__init__.py`.

```bash
rm -rf dist && uv build
uv tool run twine check --strict dist/*
```

PyPI 0.4.0 is already published — the same version cannot be uploaded twice, so
bump both version fields first. Upload with `uv tool run twine upload`, never
commit a token; pass it via `TWINE_PASSWORD` and delete any temp file.
